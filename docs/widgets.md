# iOS widgets

Home-screen and lock-screen widgets for iOS, implemented from the Claude
Design project "OnTrack Widgets" (`OnTrack Widgets.dc.html`). A widget
answers one question in one glance and never lists tasks; every shape is one
the app already uses (progress ring, goal colour edge, streak pill, 14-day
strip), so they read as OnTrack instantly.

## What ships

| Design | Widget (kind)                      | Family                           | Shows                                                                                                                                               |
| ------ | ---------------------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1a     | Today (`OnTrackToday`)             | small                            | The Today tab's summary card: ring, `3/5`, "Keep it moving · 2 left today", trophy + "All done" when the ring closes.                               |
| 1f     | Today (`OnTrackToday`)             | accessory circular / rectangular | Lock screen: the ring, and streak + "Next: …" line.                                                                                                 |
| 1d     | One goal (`OnTrackGoal`)           | medium                           | The Goals-tab card for one goal: colour edge, ring %, subtitle, streak pill, last-14-days strip.                                                    |
| 2b     | One goal, Goal = Auto              | medium                           | Default of 1d's edit sheet: the goal with the most undone work today (ties: longest streak). Shows a NEEDS YOU pill and switches only when you act. |
| 2c     | Stack of 1d                        | medium                           | Nothing to build: drop several One-goal widgets on the same spot and iOS stacks them.                                                               |
| 2a     | Goals at a glance (`OnTrackGoals`) | medium                           | Every active goal as a ring in its goal colour with the day total; a fifth goal becomes a "+N" ring.                                                |
| 1e     | Quote + ring (`OnTrackQuote`)      | medium                           | The launch-screen quote pool rotated daily, with today's ring.                                                                                      |

Colours follow the accent theme picked in Settings › Appearance (turn 3 of
the design): the Today ring, its track and the faint surface tint are built
with the app's own palette math (`Palette.swift` mirrors `ThemeContext.tsx`
and `utils/color.ts`). Goal rings keep their goal colour; only their track
and surface tint follow the accent. Light/dark follows the system
appearance of the home screen.

Taps deep-link into the app: `ontrack://today`, `ontrack://goals`,
`ontrack://goal/<id>` (parsed by `lib/widgetLinks.ts`, routed in `App.tsx`).

## How it works

Widgets cannot run JavaScript, so the app does all the thinking:

1. `lib/widgetSnapshot.ts` turns the store into a `WidgetSnapshot`: for today
   and tomorrow, the day's done/total, the next undone task, the quote of the
   day, and one `WidgetGoal` per active goal (own and shared) with the same
   percent, subtitle, streak and strip the Goals tab computes, plus the Auto
   ranking.
2. `lib/widgetSync.ts` (`useWidgetSync`, mounted in `App.tsx`) rebuilds the
   snapshot whenever goals, "Not Today" postponements or the accent change
   and on every return to the foreground.
3. `lib/widgets.ts` writes it as JSON into the shared app group
   (`group.com.adamlincodesexpo.ontrack`, key `widgetSnapshot`) through the
   local Expo module in `modules/ontrack-widgets` (`OnTrackWidgets`:
   `setSnapshot`, `reloadWidgets`) and asks WidgetKit to reload. Unchanged
   snapshots are not rewritten. Off iOS, in Expo Go and in Jest this is a
   no-op. (`@bacons/apple-targets` ships its own `ExtensionStorage` bridge,
   but its podspec needs iOS 16.4 and Expo autolinking silently skips it at
   the app's 15.1 deployment target, so the package is used only for its
   config plugin.)
4. `targets/widgets/*.swift` decodes the snapshot (`Snapshot.swift` mirrors
   the TypeScript shape; bump `version` on both sides when it changes) and
   draws it. Each timeline has an entry for now and one at local midnight
   that shows tomorrow's dues, so widgets roll over without the app opening.
   With no snapshot yet (fresh install) the widgets show sample content.

The One-goal widget's picker is an `AppIntent` (`SelectGoalIntent` +
`GoalEntity`); the entity list is read from the same snapshot, so it offers
"Auto · needs you most" plus every active goal with its colour dot.

## Building

The widgets are a native target generated by the `@bacons/apple-targets`
config plugin at prebuild time from `targets/widgets/expo-target.config.js`.
They are not available in Expo Go: use a development build or TestFlight.

- Local: `npx expo prebuild -p ios` then `npx expo run:ios` (or open
  `ios/OnTrack.xcworkspace` in Xcode; the Swift sources are linked from
  `targets/widgets`, so edit them there, never under `ios/`).
- EAS: nothing extra. The plugin registers the `widgets` extension and its
  app-group entitlement with EAS credentials for signing.
- The plugin warns when `ios.appleTeamId` is missing from `app.json`. Add the
  team ID from App Store Connect to silence it and to let local device builds
  sign the extension.

The extension's deployment target is iOS 17 (AppIntent-configured widgets);
the app itself keeps its own minimum, older devices simply don't offer the
widgets.
